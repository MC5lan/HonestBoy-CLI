# 陌生人 30 分钟测试脚本

目标：验证一个没用过 `hb` 的人，在**不给逐步指导**的情况下，30 分钟内完成安装、自检、
并跑通一个真实任务；3 人中至少 2 人成功。此文档是执行脚本，不是已完成的测试记录。

## 准备

- 干净环境：新 Windows 用户/虚拟机，或未装过 `hb` 的 Linux 用户；不要用开发者本机。
- 给参与者 release zip（或 winget 可用的版本）+ `checksums.txt`；提前说明未签名可能触发 SmartScreen。
- 准备一个临时模型端点与一次性密钥（只用于本次），以及一个**故意失败**的示例仓库
  （例如 `go test ./...` 失败，需要改一行代码）。
- 测试者不预先讲 TUI 快捷键、不讲命令，只给下面的“任务卡”。
- 征得同意后录屏/记笔记；日志和截图里不能出现真实密钥或私有代码。

参与人：P1 / P2 / P3（外部人员，非项目贡献者）。主持人：____。观察员：____。
日期：____。版本：`hb ____`。系统：____。

## 任务卡（原样交给参与者）

你有一台没装过这个工具的电脑。请在 30 分钟内：

1. 从 release 下载对应平台的包，校验 SHA256，安装并让 `hb` 能在新终端运行。
2. 运行 `hb doctor`，按提示完成首次配置；再运行 `hb probe`。
3. 在示例仓库里让 `hb` 修好失败的测试；确认它给出的完成结论有验证证据。
4. 如果中途卡住，可以先自己查 `hb --help` / `hb doctor`；仍卡住再叫主持人。

不要求使用特定命令，也不要求打开 TUI；以你自己的习惯为准。

## 主持人规则

- 开始前只读任务卡；不要演示命令，不要提示“先 init 再 doctor”。
- 参与者卡住超过 5 分钟才可给最小提示；记录提示内容和时间。
- 记录每个阶段的开始/结束时间、输入过的命令、卡点原话；不要替参与者操作。
- 发生不可恢复的环境问题（无网络、模型端点故障、无 TTY）时标记“环境阻塞”，换人重测，不计入成功/失败。
- 结束前问 3 个问题：
  1. 哪一步最不确定？当时你以为什么？
  2. 如果明天还要用，你最担心什么？
  3. 你会把它推荐给同事吗？1–5 分，为什么？

## 判定

成功 = 30 分钟内完成下列全部：

- [ ] 安装完成，`hb --version` 输出版本；
- [ ] `hb doctor` 能解释当前状态（至少配置/模型/工作区三项）；
- [ ] `hb probe` 通过；
- [ ] 示例仓库的失败测试被修好，且完成回执里有真实验证证据（或明确 `untested`，没有假 `done`）；
- [ ] 没有发生越界写文件/执行未审批高危命令。

3 人中 ≥2 人成功才过门禁。失败也要保留原始记录，不能改写成成功。
